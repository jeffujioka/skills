# opencode

- **Model list**: `opencode models`. Each line is `<provider>/<model>`. Match with the step 3 rules (family names included; skip the `~anthropic/...-latest` aliases).
- **Reasoning**: no flag. It rides on the model variant: `<provider/model>#<variant>`. There is no list of variants. A level the user named, or carried over, is tried as the variant name. The seed (below) prints `Variant unavailable for <model>: <variant>` as a `"type":"error"` line for an unknown one, and still prints a session ID. So check the output for `"type":"error"` first: on a user-named level, show the error and ask the user to pick `low`, `medium`, `high`, `max`, or no variant; on a carried-over level, run the seed again without `#variant` and say so in the report.
- **Argv**: the TUI has no model flag, so seed a session that carries the model, then open it. Both steps must hit the same server.
  - **Server.** Run `zsh -ic 'alias occ'` (the user's alias for the OpenChamber server) and strip ANSI codes. If it contains `opencode --server <url>`, use `<url>` below; otherwise use plain `opencode` with no `--server`.
  - **Seed.** The server password (`OPENCODE_PASSWORD`) exists only in the user's interactive shell, so run the seed through it, discarding stderr and stdin, keeping the output in a file: `zsh -ic "opencode run [--server <url>] -m <provider/model>[#variant] --title handoff-<slug> --format json ready" 2>/dev/null </dev/null > <out>`. Then `grep -a -c '"type":"error"' <out>` must print `0`, and `grep -a -o 'ses_[A-Za-z0-9]*' <out> | head -1` is the session ID. With no model chosen, omit `-m`. The interactive shell prints a banner before the JSON; ignore it.
  - **Open.** Run the TUI through the same interactive shell, with the first task in `--prompt`: `hc run ... zsh -ic "opencode [--server <url>] --session <sessionID> --prompt '<first task>'"`. `hc` then shows the terminal as `opencode` once it boots.
